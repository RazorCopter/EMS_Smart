# Afore EMS Companion · Issue Log

| ID | Description | Severity | Impact | Proposal | Future Milestone |
|---|---|---|---|---|---|
| CMP-01 | The live ESP32 firmware (`v5.1-console-5c`) does not emit an explicit `boot_id` UUID field in `/api/v1/ems/decision` or `ems/decision` MQTT JSON (unlike `07_DECISION_AUDIT_SCHEMA.md`). Only `seq`, `uptime_ms`, and `timestamp` are present. | Medium | Without `boot_id` on the wire, sequence resets across ESP32 reboots must be inferred in the collector by detecting `seq < prev_seq` or `uptime_ms` drops. | Collector deterministically synthesizes and persists a `boot_id` per boot session on sequence/uptime reset; optionally add `boot_id` to firmware audit JSON in a later firmware update. | M7.2 / Firmware v5.2 |
| CMP-02 | `10.0.10.10:1883` requires MQTT authentication (`CONNACK rc=5`). Credentials are stored on the ESP32 NVS / broker host and must be injected via `.env` at deployment time. | Medium | Without `MQTT_USER` and `MQTT_PASSWORD` in `.env`, live broker ingestion cannot authenticate; local stack falls back to ESP32 REST polling or dev Mosquitto simulator. | Provide credentials in `.env` during host deployment; keep `docker-compose.dev.yml` self-contained with local Mosquitto + replay bridge for offline verification. | Deploy Host |
| CMP-03 | Home Assistant SEM entities (`sensor.sem_decisione_prevista`, `sensor.sem_corrente_calcolata`, `select.solarman_modalita_ems`) are not published by `afore_esp_inputs.yaml` directly to MQTT yet. | Medium | Live SEM/ESP comparison requires HA to publish SEM state/attributes onto `afore/afore-ems/v1/sem/#` (or optional HA REST read-only fallback). | Provide ready-to-install `companion/deploy/ha/afore_companion_sem.yaml` HA package and support both MQTT SEM topics and optional read-only HA REST polling. | M7.2 / HA Setup |
| CMP-04 | PDF report export relies on browser/print-optimized HTML or lightweight server PDF generation; rich server-rendered ECharts-to-PDF rendering is deferred past MVP if headless Chromium in the API container increases ARM64 image bloat. | Low | CSV and JSON exports are complete and exact; printable report view + structured PDF summary work, while multi-chart vector PDF can be refined later. | Deliver full CSV, JSON, and print-ready / lightweight PDF report export in MVP, keeping API image lean for `linux/amd64` and `linux/arm64`. | Post-MVP C8+ |
| CMP-05 | Battery SOH (`soh`), battery temperature (`battery_temp`), grid current (`grid_a`), and inverter running status (`running`) are not yet populated by the ESP32 FC04 profile (per V51-19). | Low | Battery page and telemetry details must display `Non disponibile` / `unavailable` rather than fabricating or zero-filling these channels. | Keep fields nullable end-to-end and label `measured` vs `derived` vs `configured` vs `provisional` vs `unavailable`. | Firmware G5 |
| CMP-06 | Local prototype runs over plain HTTP inside LAN (`COMPANION_COOKIE_SECURE=false` in `.env.example`). | Medium | Session cookies travel over HTTP if not fronted by a TLS reverse proxy. | Enable TLS termination at reverse proxy and set `COMPANION_COOKIE_SECURE=true` + Entra ID / OIDC before exposing outside trusted LAN. | Hardening / Prod |
| CMP-07 | Multi-theme fonts rely on system sans fallbacks (`Inter`, `IBM Plex Sans`, `Segoe UI`) rather than self-hosted WOFF2 files. | Low | Rendering keeps zero external CDN calls and fast LAN load (< 2s), with minor glyph metric variance across OS platforms. | Keep fast system/local font stack by default; optionally bundle self-hosted `Inter`/`IBM Plex Sans` WOFF2 subsets later. | M8.2 Polish |
