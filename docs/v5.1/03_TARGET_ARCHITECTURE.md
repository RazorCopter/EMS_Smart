# Target architecture

The ESP32-S3-Relay-1CH is the single Modbus RTU master and the autonomous EMS. Its C++17 core and electrical safety are independent of every network service. The first release has one operating mode, SHADOW, and computes decisions against live telemetry when available.

| Layer | Responsibilities | Authority boundary |
|---|---|---|
| ESP32-S3 | Fixed Afore AF5K-SL reader, validation, Energy State, pure strategies, scheduler, Safety Engine, sole Command Arbiter and Shadow executor, AUX facade, audit, watchdog, diagnostics, persistent validated config, MQTT client, REST and minimal Web Setup | Sole decision authority; accepts bounded configuration and expiring advice. Local settings and last valid policy govern offline behavior. |
| Optional Home Assistant | PV/Solcast and load forecast, prices, target SOC, requested strategy, schedule hint, temporary overrides, optimization advice, discovery and visual supervision | Authenticated advisory MQTT topics; local capability and policy set the ceiling. Lease validation, Safety and Arbiter stay on the ESP. |
| Optional external container | Ingest ESP audit, historical DB, dashboard and diagnostics, compare SHADOW proposal with observed native behavior, CSV/JSON export, advanced configuration through authenticated ESP REST | No bus access, core dependency or control algorithm. Container may use already available external host/container infrastructure. |

## Interfaces and starting settings

Use MQTT namespace `ems/<id>/v1/` with retained `availability` and latest `state`, non-retained `decision` and `advice_ack`, and ACL-scoped advisory intake `advice/{pv_forecast,load_forecast,tariffs,target_soc,strategy,schedule,override,optimization}`. Normalize source ID, message version, revision, issue/expiry UTC, policy scope and payload into one typed mailbox. Check sender authority, freshness, maximum payload and request ordering before acceptance. Acknowledge acceptance or rejection and reason. Apply expiry at the earlier of accepted UTC expiry and local monotonic deadline. Ignore retained overrides on subscribe. Local config sets permissions, and tighter caps always win. REST exposes versioned health, state, capabilities, decision pages and authenticated config read/patch with an expected revision. Web Setup uses that same REST configuration contract.

During bring-up, evaluate proposed cadence 1 Hz decisions and 2–5 s essential telemetry polls, max essential age 5 s and skew 2 s, subject to measured bus occupancy. Configure SOC reserve, ceiling and hysteresis, max charge/discharge, grid exchange target, export ceiling, deadband and ramp, schedule timezone/deadlines and advisory TTLs. Initial deadband ±20 W and slew 250 W/s are starting replay parameters from the previous plan. In-service values require G5/G6 characterization. Leave numerical battery thresholds and charging permissions unqualified until the battery model/capabilities are known. Choose Safe Mode for strategies that depend on them.

## Local composition

`RS485 owner → profile reader → per-field quality → immutable EnergyState → scheduler → strategy intention → CommandArbiter/Safety Engine → ShadowCommandExecutor → DecisionAudit`

Only one task owns UART and serial timing. Poll I/O runs with bounded deadlines and backoff. It publishes immutable timestamped snapshots. The decision scheduler uses a monotonic clock at a proposed 1 Hz. The Arbiter is the only consumer of the safety verdict and always invokes the no-I/O executor with the accepted disposition. Other tasks consume snapshots or submit typed advice. Network reconnect, serialization and exports run outside the decision path through bounded queues, with no locks held across I/O. Feed the task watchdog after progress on bounded tasks and record reset reasons. Unplugging Wi-Fi, MQTT, HA or analytics leaves the same local scheduler, stale checks and safe policy available.

- EnergyState fields include value or null, unit, provenance, per-field age, validity/quality and acquisition window. Grid power is positive import, battery power positive charge, PV nonnegative DC, and load nonnegative AC. Keep raw register bits, scaling and sign visible in diagnostic fixtures. Decode once at the driver boundary. Derived load from AC output plus grid import requires a documented AC topology and coherent timestamps.
- Afore primary source is the FC04 vendor/profile path. Use trusted ranges and word/byte order from fixture and captures. Null and retained last-known value with age are distinct. Missing/stale/unsupported data cannot be promoted to valid by fallback or formatting. Corrupt reads, sample skew and status/limits/BMS data affect the safety result.
- Authority order is hard safety veto, Safe Mode, locally approved maintenance or schedules under scope policy, valid advisory lease if enabled, then configured local strategy. Native Inverter leaves authority with the inverter while telemetry/audit continue. Expired remote inputs fall back to configured local policy, or Safe Mode for unusable critical data. All candidates pass the same Safety Engine. Critical restrictions apply immediately ahead of smoothing.
- Config is versioned, schema-validated and atomic with generation/CRC and previous valid generation. Use expected revision for edits. Default is read-only SHADOW, AUX disabled, grid charging disallowed and Native Inverter or Safe Mode until local configuration/telemetry qualifies. Persist configuration edits only; leases live in RAM. Web Setup exposes network and allowed strategy parameters/thresholds with authenticated localized access, redacted secrets and no generic command route.
- UTC from valid RTC or network sync annotates the monotonic scheduler. Clock jumps cannot revive leases. Require trustworthy UTC for external issuance/expiry validation and schedule interpretation. Store schedule timezone explicitly, handle DST folds/gaps deterministically and use monotonic time for lease runtime and durations.
- Shared evidence model follows [audit schema](07_DECISION_AUDIT_SCHEMA.md). G10 uses observed plant behavior and declared counterfactuals with different provenance.
