# Clean restart plan

The v5.1 reference is this dossier. Preserve the earlier Heliograph/OpenEMS plans and artifacts for provenance. The Waveshare 1CH owns physical acquisition and local EMS. A desktop native harness and simulator support development. Home Assistant and external analytics are optional integrations.

1. **Freeze the as-found baseline.** Record HEAD, branch, index, path-by-path status and content fingerprints as in [assessment](01_CURRENT_STATE_ASSESSMENT.md). Preserve untracked registers, OpenEMS plans, C3 work and EMS core changes. In the implementation mission, build from an isolated checkout derived from HEAD with selected reviewed changes applied deliberately. Use Git worktree or an isolated copy as appropriate after documenting its provenance. Leave the original branch and local changes intact.
2. **Adopt a single execution composition.** Use the board pin map, PIO/Arduino HAL, validated RTC helpers, diagnostic conventions and MIT code in small dependency slices. Keep legacy target matrix intact while defining new diagnostic and SHADOW source allowlists. Reuse only approved read functions in the physical image.
3. **Consolidate telemetry.** Use vendor FC04/TOML as the sole Afore mapping. Remove the alternate FC03 implementation from the new compile graph. Use old Python and older captures to build independent decoder fixtures where provenance permits. Retain profile/version and raw measurement evidence, with quality and signs qualified in G4/G5.
4. **Consolidate calculation.** Extract tested pure logic from multiple EMS drafts, selecting one C++17 contract and one scheduler/Arbiter/Safety chain. Port strategy math in reviewable slices. Remove duplicate authority layers from composition, retain earlier source for comparison while validating behavior.
5. **Integrate optional services.** After local qualification, re-use MQTT reconnection/discovery and setup UI patterns with safe endpoint allowlists. Avoid the legacy command and OTA surface. Build the external analytics consumer against the common audit model.
6. **Keep archive boundaries.** Previous M0–M3 intentions inform G0/G5/G6. M4–M7 become the G6 strategy sequence and G7 input validation. M8–M10 inform G7/G8/G9. Former host deployment M11 is archived. M12 maps to G2–G6. M13 write encoding stays outside SHADOW. M14 becomes the separate G11 assessment. M15 becomes evidence-driven G10.
7. **Review future removal after a qualified release.** Historical `deploy/install_raspberry.sh`, systemd unit and Python backend, ARM64 packaging, old release binaries, update tools and legacy goals are exclusion/archive candidates. Leave other Heliograph platforms as legacy consumers unless a separate scope explicitly retires them.

During each future gate freeze the exact config, inputs and produced binary before advancing. If a gate fails, narrow the feature composition, return to the last qualified artifacts and keep failed evidence. Runtime or hardware tests use the serial/protocol permissions of their own mission.
